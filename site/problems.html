ModuleNotFoundError: No module named 'requests'

ModuleNotFoundError: No module named 'requests'

Symptom

Works in your terminal, fails under cron, systemd, sudo or CI; or fails right after creating a new venv.

Why it happens

  • A different interpreter runs the script than the one you installed into (system python3 instead of the venv)
  • The package was never installed in this environment
  • The import name differs from the package name (yaml is PyYAML)

Confirm

python3 -c 'import sys; print(sys.executable)'
python3 -m pip show requests
head -1 script.py   # which interpreter the shebang names

Fix

Run the script with the environment's own interpreter (/opt/app/.venv/bin/python script.py), or install the package into the interpreter that runs it with python -m pip install.

Prevent

One venv per application, a pinned requirements.txt, and absolute interpreter paths in crontabs and unit files.

ImportError: cannot import name 'x' from 'y'

ImportError: cannot import name 'Retry' from 'requests.packages.urllib3' (unknown location)

Symptom

An import that used to work fails after a dependency upgrade, or a module imports itself.

Why it happens

  • The name moved or was removed in a new major version
  • A local file shadows the library (a json.py or requests.py next to your script)
  • A circular import between two of your modules

Confirm

python3 -c 'import y; print(y.__file__, getattr(y, "__version__", "?"))'
ls *.py   # anything named like the library?
pip index versions y

Fix

Import from the library's current location, or pin the version your code was written for; rename local files that shadow libraries.

Prevent

Pin dependencies, read changelogs before major upgrades, and never name your files after modules.

error: externally-managed-environment

error: externally-managed-environment

× This environment is externally managed

Symptom

pip install (also with --user or sudo) is refused on a current Debian, Ubuntu or Fedora system.

Why it happens

  • The system Python's packages belong to the OS package manager (PEP 668)
  • pip would overwrite files apt or dnf installed

Confirm

ls /usr/lib/python3*/EXTERNALLY-MANAGED
python3 -m pip --version

Fix

Create a venv and use its pip and python: python3 -m venv .venv && .venv/bin/pip install -r requirements.txt. For command-line tools, pipx install <tool>. Use apt for OS-wide Python packages.

Prevent

Never install into the system Python; avoid --break-system-packages.

source: not found (activating a venv in cron or sh)

/bin/sh: 1: source: not found

Symptom

A crontab line or sh script that activates a virtual environment fails, or the venv is not used.

Why it happens

  • cron and many CI steps run /bin/sh (dash), which has no source
  • Activation only changes PATH for the current shell; it is never needed in automation

Confirm

ls -l /bin/sh
/opt/app/.venv/bin/python -c 'import sys; print(sys.prefix)'

Fix

Do not activate: call /opt/app/.venv/bin/python script.py directly. In sh, . (dot) is the POSIX spelling of source.

Prevent

Use absolute venv interpreter paths in crontabs, systemd units and CI steps.

Symptom

Date arithmetic fails between a time from an API and datetime.now().

Why it happens

  • datetime.now() and utcnow() are naive (no time zone); ISO times with +00:00 are aware

RecursionError: maximum recursion depth exceeded

RecursionError: maximum recursion depth exceeded

Symptom

A recursive walk or a function that calls itself crashes after about a thousand levels.

Why it happens

  • No base case, or one that is never reached
  • Following a cycle: symlinks, parent links, a property that calls itself

SSLError: CERTIFICATE_VERIFY_FAILED

requests.exceptions.SSLError: ... [SSL: CERTIFICATE_VERIFY_FAILED] certificate verify failed: unable to get local issuer certificate (_ssl.c:1032)

Symptom

HTTPS to an internal service fails, often only from Python.

Why it happens

  • The server uses a private CA that requests (certifi) does not trust
  • The server does not send its intermediate certificate
  • An expired certificate, or a name mismatch
  • A TLS-inspecting proxy

Confirm

openssl s_client -connect host:443 -servername host -showcerts </dev/null
python3 scripts/cert_checker.py host:443

Fix

Trust the right CA: verify='/etc/ssl/certs/corp-root-ca.pem' or REQUESTS_CA_BUNDLE; fix the server's chain if it is incomplete. Never verify=False.

Prevent

Distribute the company CA bundle to hosts and CI; monitor expiry with cert_checker.py.

Catch subprocess.TimeoutExpired per host, report it, and carry on with the others.

Prevent

A timeout on every command that touches the network; BatchMode for ssh.

RuntimeWarning: coroutine was never awaited

RuntimeWarning: coroutine 'sleep' was never awaited

Symptom

An async call seems to do nothing.

Why it happens

  • Calling a coroutine function without await only creates the coroutine

Confirm

python3 -X dev script.py

Fix

Add await (await asyncio.sleep(1)), or schedule it with asyncio.create_task.

Prevent

Run asyncio code with -X dev in tests; it reports blocking calls and unawaited coroutines.

Now learn it: break and fix it yourself in time.sleep inside async code, then take Level 09 · Concurrency. Interactive version: #fix/neverawaited.

ModuleNotFoundError: No module named 'distutils'

ModuleNotFoundError: No module named 'distutils'

Symptom

A script breaks after an OS or Python upgrade to 3.12 or later.

Why it happens

  • distutils was removed from the standard library in Python 3.12 (PEP 632)
  • Other removals: imp, asynchat, asyncore, smtpd (3.12); cgi, crypt, telnetlib, pipes (3.13)

Confirm

python3 -V
python3 -W error::DeprecationWarning script.py   # on the old version

Fix

Replace the module: version comparison with tuples of ints or packaging.version; imp with importlib; pipes.quote with shlex.quote.

Prevent

Run tests with deprecation warnings as errors before upgrading.

Now learn it: break and fix it yourself in No module named 'distutils', then take Level 13 · Boss level: the night shift. Interactive version: #fix/distutilsgone.
